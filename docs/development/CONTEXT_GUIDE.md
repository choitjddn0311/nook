# 컨텍스트 관리 가이드

> Claude와 개발할 때 컨텍스트(대화 기억)를 아끼고, 개발 이력을 잃지 않기 위한 기준 문서. CLAUDE.md의 "컨텍스트 관리" 규칙이 이 문서를 따른다.

## 어디에 무엇을 남기나

| 위치 | 담는 것 | 특징 |
|---|---|---|
| `docs/development/HANDOFF.md` | **지금 상태**: 끝난 기능, 진행 중인 작업, 미해결 문제, 다음 작업 | 저장소에 남는 진짜 기록. 세션이 바뀌어도, 다른 기기에서도 그대로 |
| `docs/roadmap.md` | 단계별 진행표, 지난 결정 | 큰 흐름과 이력 |
| `docs/architecture.md` · `docs/design.md` · `docs/api.md` | 구조·디자인·API의 현재 사실 | 코드와 같은 PR에서 고친다 |
| Claude 메모리 (`~/.claude/projects/…/memory/`) | 사용자 취향, 작업 방식, 자주 걸리는 함정, HANDOFF 요약 | 이 Mac의 Claude만 읽음. 저장소에 없으므로 **진짜 기록은 문서에** |
| 대화 기록 | 지금 하는 일 | `/clear`나 맥락 압축 때 사라질 수 있다 |

원칙: **개발 진행 상황은 대화에만 두지 않고 문서에 남긴다.** 메모리는 빨리 찾기 위한 요약이고, 사실의 기준은 저장소 문서다.

## 언제 무엇을 하나

| 때 | 할 일 |
|---|---|
| 새 작업을 시작할 때 | 메모리의 인수인계 요약과 `HANDOFF.md`를 확인한다. 작업에 필요한 docs 문서만 연다 |
| 주요 단계가 끝났을 때 (PR 병합 등) | `HANDOFF.md`의 끝난 기능·다음 작업을 고치고, 메모리 요약도 맞춘다 |
| 새 작업으로 넘어가거나 세션을 새로 시작할 때 | `HANDOFF.md`가 최신인지 확인한다(진행 중 브랜치, 미해결 문제 포함) |
| 사용자가 `/clear` 하려 할 때 | 먼저 중요한 내용이 문서에 저장됐는지 확인하고 안내한다. 저장 안 된 것이 있으면 저장부터 |
| 같은 작업을 이어갈 때 | 세션을 새로 시작하자고 하지 않는다. 맥락이 많이 찼으면 문서를 갱신한 뒤 사용자가 고르게 한다 |

## 컨텍스트를 아끼는 법
- 파일 전체를 출력하거나 읽지 않는다. 필요한 부분만 찾아서(`grep`) 범위를 정해 읽는다.
- 이미 아는 구조를 다시 분석하지 않는다. 문서(`docs/*.md`)에 있으면 문서를 본다.
- 명령 결과는 필요한 줄만 보이게 한다(`tail`, `grep`, `head`).
- 설명은 짧게, 결과와 다음 할 일 중심으로.

## 사실과 기억을 구분하기
- 문서나 코드에 없는 내용을 이미 구현된 사실처럼 말하지 않는다.
- 메모리·인수인계 문서의 내용도 시간이 지나면 틀릴 수 있다. 파일 이름·함수·설정을 말하기 전에 코드에서 한 번 확인한다.
- 확인하지 못한 것은 "확인 안 됨"으로 적는다.
